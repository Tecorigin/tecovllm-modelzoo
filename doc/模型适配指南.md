# 算子性能优化比赛指南

> **注意**：提交代码前务必阅读文末 [第 6 节 提交说明](#6-提交-pr)，确保 run.sh 满足所有要求。

本文档面向参赛开发者，介绍如何在太初 AI 加速卡（SDAA 平台）上对 **Intern-S2-Preview** 和 **OneGenomeRice** 两个模型进行算子性能优化。整体流程如下：

| # | 阶段 | 说明 |
|---|------|------|
| 1 | 检查推理环境 | 确认开发环境（硬件 + 容器）满足任务需求 |
| 2 | 模型适配 | 模型分析 → 算子优化 → 运行验证 |
| 3 | 精度验证 | 验证推理精度是否达标 |
| 4 | 性能评测 | 测试吞吐、延迟等关键指标 |
| 5 | 添加 README | 为优化后的模型编写使用说明 |
| 6 | 提交代码 | 完成所有测试后提交 |

---

## 1. 检查推理环境

开始适配前，建议先熟悉开发环境的软硬件配置，确保容器、框架、加速卡等资源就绪，以便适配和推理过程顺利进行。

### 1.1 检查硬件信息

使用 `teco-smi` 命令查看太初加速卡的设备列表与工作状态：

```bash
teco-smi
```

输出示例：

```
+-----------------------------------------------------------------------------+
|  TECO-SMI: 1.15.0        SDAADriver: 3.1.0        SDAARuntime: 3.1.0        |
|-------------------------------+----------------------+----------------------|
| Index  Name                   | Bus-Id               | Health      SPE-Util |
|        Temp          Pwr Usage|          Memory-Usage|                      |
|=============================================================================|
|   0    TECO_AICARD_01         | 00000002:05:00.0     | OK                0% |
|        42C                98W |        0MB / 65536MB |                      |
|-------------------------------+----------------------+----------------------|
|   1    TECO_AICARD_01         | 00000002:06:00.0     | OK                0% |
|        40C                92W |        0MB / 65536MB |                      |
+-------------------------------+----------------------+----------------------+
```

重点关注以下字段：

| 字段 | 说明 | 正常状态 | 异常处理 |
|------|------|----------|----------|
| **Memory-Usage** | 设备内存使用状态（已用 / 总量） | 已用内存远小于总量 | 内存占用异常时检查残留进程 |
| **Health** | 设备健康状态 | `OK` | 出现 `DEVICE_LOST`、`HEARTBEAT_ERROR` 等异常时，请联系太初技术支持 |
| **SPE-Util** | SPE 计算核心使用率 | 正常数值 | 显示 `N/A` 表示芯片掉卡，请联系太初技术支持 |

## 2. 模型适配

### 2.1 模型分析

适配前请完成以下分析，以保障后续流程顺利开展：

1. **模型可运行验证**：确认模型在 CPU 或 GPU 环境下能正常加载并完成基础推理，无报错或异常退出。
2. **量化格式确认**：当前仅支持 **FP16** 和 **INT8** 两种量化格式，其他格式暂不兼容。
3. **并行策略确认**：
   - **TP（张量并行）**：按硬件核组数配置，单卡为 4 核组，单卡运行时 TP = 4。
   - Intern-S2-Preview 使用 TP=8（2 张卡），OneGenomeRice 使用 TP=4（1 张卡）。
   - **PP / DP / EP**：并行规则与标准 CUDA 保持一致。
4. **算子选择**：以下算子已在 [算子开发仓库](https://github.com/Tecorigin/teco-ops) 中提供基础版本，参赛者可在此基础上进行性能优化：

| 算子 | 适用模型 | 说明 |
|------|----------|------|
| `reshape_and_cache_flash` | Intern-S2-Preview、OneGenomeRice | KV cache 写入与 reshape 融合算子 |
| `flash_attn_varlen_func` | Intern-S2-Preview、OneGenomeRice | 变长 Flash Attention 前向算子 |
| `causal_conv1d_fn` | OneGenomeRice | Mamba 架构因果卷积算子 |

### 2.2 算子优化

参赛者可基于上述基础版本进行性能优化（如算子融合、优化特定 shape 下的算子性能等）。算子优化及 PyTorch 框架接入方法，请参考 [算子开发仓库](https://github.com/Tecorigin/teco-ops) 中的相关文档。

> ⚠️ **注意**：优化过程中请**仅修改算子内部实现**，保持对外 API 接口不变。接口变更将导致模型组网层和注册层需要额外适配，增加不必要的工作量。

### 2.3 运行模型

#### 2.3.1 离线推理

参考 [离线推理文档](http://docs.tecorigin.com/release/teco_vllm/v3.1.0/#d6692347dc1c533ab3651f83213ae646)，完成模型离线推理验证。

#### 2.3.2 在线推理

参考 [在线推理文档](http://docs.tecorigin.com/release/teco_vllm/v3.1.0/#43351f4b9e305913b221a171b0a5a59d)，完成模型在线推理验证。

## 3. 精度验证

模型适配完成后，需通过精度验证确认推理结果正确性。具体流程如下：

### 3.1 精度测试

**环境要求**：vLLM 版本为 **0.20.2**，Evalscope 版本为 **1.8.1**。

> **采样参数**：各模型的采样参数（temperature、top_p、top_k 等）均使用模型官方推荐的设置方式。

#### Shanghai_AI_Laboratory/Intern-S2-Preview

**评测数据集**：evalscope 自定义数据集 `interns2_custom`

> ⚠️ **注意**：该自定义数据集目前尚未就绪，待后续提供。以下命令基于预期配置编写，实际运行时需确认数据集可用性。

**启动 vLLM 服务**（TP=8）：

```bash
vllm serve /tecogpfs/models/Shanghai_AI_Laboratory/Intern-S2-Preview \
    --trust-remote-code \
    --tensor-parallel-size 8 \
    --mm-encoder-tp-mode data \
    --mm-processor-kwargs '{"max_pixels": 501760, "min_pixels": 3136}' \
    --mamba-ssm-cache-dtype float32 \
    --enforce-eager \
    --port <port> \
    --host <ip>
```

**运行 Evalscope 评测**：

```bash
evalscope eval \
    --model /tecogpfs/models/Shanghai_AI_Laboratory/Intern-S2-Preview \
    --api-url http://<ip>:<port>/v1/chat/completions \
    --api-key EMPTY_TOKEN \
    --datasets interns2_custom \
    --eval-batch-size 32 \
    --generation-config do_sample=true,temperature=0.7,top_p=0.8,top_k=50 \
    --ignore-errors
```

#### zhejianglab/OneGenomeRice

**评测数据集**：Epigenetic_Marks_Prediction-Histone（来自 RiceBenchmark）

**启动 vLLM 服务**（TP=4）：

```bash
vllm serve /tecogpfs/models/zhejianglab/OneGenomeRice \
    --trust-remote-code \
    --tensor-parallel-size 4 \
    --port <port> \
    --host <ip>
```

**运行 epi_eval.py 评测**：

```bash
python tools/ci_pipline/epi_eval.py \
    --host <ip> \
    --port <port> \
    --predict-bases 100 \
    --max-samples 50 \
    --workers 10 \
    --data-dir /home/RiceBenchmark
```

### 3.2 精度评测基准

各模型评测 10 次取平均分，波动不得超过基线 ±0.05。具体要求见下表。

| 模型 | 数据集 | 子集 | Case 数 | 评分指标 | 基准得分 |
|------|--------|------|---------|----------|----------|
| Intern-S2-Preview | interns2_custom | - | TBD | mean_acc | TBD（⏳ 自定义数据集待提供，脚本路径: `tools/ci_pipline/precision_result.json`） |
| OneGenomeRice | epi_eval | Epigenetic_Marks_Prediction-Histone | 50 | accuracy | 0.6902（使用 `tools/ci_pipline/epi_eval.py` 跑分） |

## 4. 性能评测

### 4.1 性能测试

SDAA 平台所有模型的性能评测统一使用 **Evalscope** 框架。通过 Evalscope 指定模型服务 API 端点和数据集进行推理性能压测，得到吞吐量（tokens/s）和请求延迟（TTFT、TPOT）等关键指标。

以下为 Intern-S2-Preview 和 OneGenomeRice 的文本性能测试用例（T1 ∼ T3）：

#### T1 — 固定长度（IN:128 / OUT:128）

```bash
evalscope perf \
    --parallel '[[128, 128, 1000]]' \
    --url http://<ip>:<port>/v1/chat/completions \
    --model <model_name> \
    --api-key EMPTY_TOKEN \
    --number 1000 \
    --tokenizer-path <model_path> \
    --eval-mode customized
```

#### T2 — 固定长度（IN:2048 / OUT:128）

```bash
evalscope perf \
    --parallel '[[2048, 128, 1000]]' \
    --url http://<ip>:<port>/v1/chat/completions \
    --model <model_name> \
    --api-key EMPTY_TOKEN \
    --number 1000 \
    --tokenizer-path <model_path> \
    --eval-mode customized
```

#### T3 — 固定长度（IN:2048 / OUT:2048）

```bash
evalscope perf \
    --parallel '[[2048, 2048, 1000]]' \
    --url http://<ip>:<port>/v1/chat/completions \
    --model <model_name> \
    --api-key EMPTY_TOKEN \
    --number 1000 \
    --tokenizer-path <model_path> \
    --eval-mode customized
```

### 4.2 性能指标

| 指标 | 含义 | 说明 |
|------|------|------|
| `TTFT`（ms） | 首 token 延迟 | 请求到达 → 生成首个 token 的耗时 |
| `TPOT`（ms） | 每 token 延迟 | 生成阶段每个 token 的间隔时间 |
### 4.3 性能测试用例汇总

| 用例 | 类型 | IN | OUT | Number | 适用模型 |
|------|------|-----|------|--------|----------|
| T1 | 短文本 | 128 | 128 | 1000 | 全部 |
| T2 | 中文本 | 2048 | 128 | 1000 | 全部 |
| T3 | 长文本 | 2048 | 2048 | 1000 | 全部 |

## 6. 提交代码

模型适配完成并跑通全部测试用例后，即可将新增的模型文件及 README 推送到远程仓库。

### 6.1 预检查清单

提交 PR 前请逐项确认：

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | 推理功能正常 | vLLM 在线推理服务能正常启动并响应 /v1/chat/completions 请求 |
| 2 | 精度达标 | SDAA 精度与 基线在允许偏差内 |
| 3 | 性能达标 | 吞吐量不低于 基线的 80% |
| 4 | README 齐全 | 模型保存目录下包含 README 文件 |

### 6.2 评测说明

**你的 run.sh 脚本必须放在对应模型的路径下**，CI 会根据仓库目录自动扫描并调度执行。CI 将依据你的 run.sh 中定义的配置自动执行精度和性能测试，通过标准见 [3.2 精度评测基准](#43-精度评测基准) 和 [4.2 性能指标](#52-性能指标)。

> 预提交 CI 会校验 run.sh 中 **至少一项类型** 跑通。请在 `served-model-name` 中只包含 **已适配完成** 的模型。

当前 `run.sh` 中 `served-model-name` 的配置示例：

```bash
served-model-name=(
    "Intern-S2-Preview"
    "OneGenomeRice"
)
```

### 6.3 提交规范

- **分支命名**：`feat/adapt-<模型名称>`
- **Commit 信息格式**：`feat: adapt <模型名称> for SDAA platform`
- **PR 描述**：须包含精度对比表（基线 vs SDAA 实测）和 T1-T3 性能对比表

## 附录

### A. 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| vLLM 启动报 `CUDA out of memory` | 显存不足 | 增大 TP size 或减小 max_model_len |
| Evalscope 评测报 `Connection refused` | vLLM 服务未启动或端口错误 | 检查端口和服务状态 |
| 精度波动超过 ±0.05 | 可能存在算子数值精度问题 | 按 4.4 节排查流程定位 |

### B. 术语对照

| 缩写 | 全称 | 说明 |
|------|------|------|
| SDAA | Smart Data & AI Accelerator | 太初 AI 加速卡 |
| TP | Tensor Parallelism | 张量并行 |
| TTFT | Time To First Token | 首 token 延迟 |
| TPOT | Time Per Output Token | 每 token 延迟 |
