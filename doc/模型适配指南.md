# 算子性能优化比赛指南

本文档面向参赛开发者，介绍如何在太初 AI 加速卡（SDAA 平台）上对 **OneGenomeRice** 模型进行算子性能优化。整体流程如下：

| # | 阶段 | 说明 |
|---|------|------|
| 1 | 环境准备 | 拉取仓库 → 进入容器 |
| 2 | 模型适配 | 模型分析 → 算子优化 → 运行验证 |
| 3 | 精度验证 | 验证推理精度是否达标 |
| 4 | 性能评测 | 测试吞吐、延迟等关键指标 |
| 5 | 评测说明 | CI 评测流程与注意事项 |

---

## 2. 模型适配

### 2.1 模型分析

适配流程：先验证模型可运行，再进行算子性能优化。

**步骤 1：启动 vLLM 服务，验证模型可运行**

使用以下固定命令启动 vLLM 推理服务：

```bash
vllm serve /path/to/model \
    --trust-remote-code \
    --tensor-parallel-size 4 \
    --max-model-len 131072 \
    --gpu-memory-utilization 0.95
```

> 启动成功后可发送简单推理请求，确认模型正常加载、无报错。

**步骤 2：算子性能优化**

验证通过后，进入算子优化阶段。需优化的算子如下，具体优化方法见 [2.2 算子优化](#22-算子优化)。

| 算子 | 说明 |
|------|------|
| `reshape_and_cache_flash` | KV cache 写入与 reshape 融合算子 |
| `flash_attn_varlen_func` | 变长 Flash Attention 前向算子 |

### 2.2 算子优化

**优化指导建议**：

1. 充分理解算法逻辑，设计实现方案时可以结合数学公式看是否可从计算上进行优化
2. 分析算法细节，合理设计任务的粒度和负载均衡，充分发挥众核架构多核心的优势进行并行操作（任务拆解到多个核心并行处理）
3. 充分利用 SPM 优势将数据尽可能多的重复利用，减少主存数据搬运
4. 根据情况可考虑是否需要额外的主存来存储中间计算结果，或者对部分数据进行重计算
5. 一些常用的优化手段包括：双缓冲，向量化计算，负载均衡，主存数据连续搬运等

更详细的性能优化指导，可查阅 [性能优化手册-算子篇](http://docs.tecorigin.com/release/op_perf_opt/v1.1.0/#5728df579b864ac3a8b108b812e60611)。

> ⚠️ **注意**：优化过程中请**仅修改算子内部实现**，保持对外 API 接口不变。接口变更将导致模型组网层和注册层需要额外适配，增加不必要的工作量。

### 2.2.1 自定义算子库编译安装

自定义算子库编译：

1. 在项目目录下构建自定义算子库 `wheel` 包：

   ```bash
   # 导入Tecorigin软件栈环境变量
   source /opt/tecoai/setvars.sh
   # 构建teco-ops wheel包，仅构建PyTorch 扩展（不包含 Plugin）
   WITH_TORCH=ON WITH_INFERENCE_PLUGIN=OFF python setup.py bdist_wheel
   ```

2. 安装 tecoops 自定义算子库：

   - 构建完成后在项目 `dist` 目录下生成 `tecoops-0.0.0-cp312-cp312-linux_loongarch64.whl` 包
   - 执行 `pip install tecoops-0.0.0-cp312-cp312-linux_loongarch64.whl` 安装。

3. 卸载 tecoops 自定义算子库：`pip uninstall tecoops -y`

4. 更新 tecoops 自定义算子库，提供两种方式：

   - 方式一：先卸载旧的 `tecoops`，再安装新的。
   - 方式二：执行 `pip install tecoops-0.0.0-cp312-cp312-linux_loongarch64.whl --force-reinstall` 强制更新。

## 3. 精度验证

模型适配完成后，需通过精度验证确认推理结果正确性。具体流程如下：

### 3.1 精度测试

**环境要求**：vLLM 版本为 **0.20.2**，Evalscope 版本为 **1.8.1**。

> **采样参数**：各模型的采样参数（temperature、top_p、top_k 等）均使用模型官方推荐的设置方式。

#### zhejianglab/OneGenomeRice

**评测数据集**：使用 RiceBenchmark 数据集 Epigenetic_Marks_Prediction-Histone 子集的 test 部分作为测试数据。
**评测方法**：测试模型根据之前的碱基对生成最后一百个碱基的正确性，评价指标使用准确率（accuracy）。
**测试数据**：评测时 `epi_eval.py` 会自动从 ModelScope 下载，无需手动准备。

https://www.modelscope.cn/datasets/ZhejiangLab/RiceBenchmark/resolve/master/Epigenetic_Marks_Prediction-Histone/test.jsonl

**启动 vLLM 服务**（TP=4）：

```bash
vllm serve /tecogpfs/models/zhejianglab/OneGenomeRice \
    --trust-remote-code \
    --tensor-parallel-size 4 \
    --port <port> \
    --host <ip>
```

**运行 epi_eval.py 评测**：

```bash
python tools/ci_pipline/epi_eval.py \
    --host <ip> \
    --port <port> \
    --workers 128 \
```

### 3.2 精度评测基准

各模型评测 10 次取平均分，波动不得超过基线 ±0.02。具体要求见下表。

| 模型 | 数据集 | 子集 | Case 数 | 评分指标 | 基准得分 |
|------|--------|------|---------|----------|----------|
| OneGenomeRice | RiceBenchmark | Epigenetic_Marks_Prediction-Histone | 10000 | accuracy | 0.9024 |

---

### 3.3 精度分析工具

若精度不达标，可使用精度分析工具定位差异来源：

| 工具 | 说明 | 参考文档 |
|------|------|----------|
| **精度分析工具** | 当模型精度异常时，使用该工具逐层对齐 CUDA 与 SDAA 的推理精度，定位精度异常的层，帮助加快精度排查进度 | [精度分析工具使用指南](http://docs.tecorigin.net/release/teco_precision/) |

> **精度基线建议**：使用基础版算子 dump 各层的矩阵值作为基线，供精度分析工具逐层对齐时参考对照。

> **注意**：该工具只能排查每层是否存在精度问题，无法定位到具体算子。


## 4. 性能评测

### 4.1 性能测试

SDAA 平台所有模型的性能评测统一使用 **Evalscope** 框架。通过 Evalscope 指定模型服务 API 端点和数据集进行推理性能压测，得到吞吐量（tokens/s）和请求延迟（TTFT、TPOT）等关键指标。

以下为 OneGenomeRice 的文本性能测试用例（T1 ∼ T4）。

> **变量说明**：
> - `$MODEL_NAME`：模型名称，即 `vllm serve` 启动时 `--served-model-name` 的值
> - `$API_URL`：vLLM 服务地址，格式为 `http://<host>:<port>/v1/completions`
> - `$MODEL_PATH`：模型文件所在路径，与 `vllm serve` 的 model 参数一致

#### T1 — bs=1，16K 输入 / 200 输出

```bash
evalscope perf \
    --model "$MODEL_NAME" \
    --url "$API_URL" \
    --api openai \
    --tokenizer-path "$MODEL_PATH" \
    --dataset random \
    --min-prompt-length 16384 --max-prompt-length 16384 \
    --max-tokens 200 --min-tokens 200 \
    --extra-args '{"ignore_eos": true}' \
    --parallel 1 --number 10
```

#### T2 — bs=1，32K 输入 / 200 输出

### 4.2 性能指标

| 指标 | 含义 | 说明 |
|------|------|------|
| `TTFT`（ms） | 首 token 延迟 | 请求到达 → 生成首个 token 的耗时 |
| `TPOT`（ms） | 每 token 延迟 | 生成阶段每个 token 的间隔时间 |

|------|-----|----------|----------|--------|

| T2 | 1 | 32K | 200 | 10 |
| T3 | 1 | 64K | 200 | 10 |
| T4 | 1 | 100K | 200 | 10 |

### 4.4 性能评分规则

满分 **50 分**，T1∼T4 四个 case 的 TTFT、TPOT 加权计算。以最慢基线 $B$ 和最优参考 $Best$ 做线性归一化。

#### 权重

| Case | 权重 | 指标 | 单项满分 |
|------|:----:|------|:--------:|
| T1 (16K→200, bs=1) | 0.25 | TTFT / TPOT | 各 6.25 |
| T2 (32K→200, bs=1) | 0.25 | TTFT / TPOT | 各 6.25 |
| T3 (64K→200, bs=1) | 0.25 | TTFT / TPOT | 各 6.25 |
| T4 (100K→200, bs=1)| 0.25 | TTFT / TPOT | 各 6.25 |

#### 公式

$$
\text{Score}_{i,M} = \frac{B_{i,M} - \text{Actual}_{i,M}}{B_{i,M} - \text{Best}_{i,M}} \times w_i \times 25
$$

| 符号 | 含义 |
|------|------|
| $B_{i,M}$ | 最慢基线值（未优化参考实现） |
| $\text{Best}_{i,M}$ | 最优参考值（理论或实测最快） |
| $\text{Actual}_{i,M}$ | 实测值 |

- Actual = $B$（最慢）→ **0 分**；Actual = $Best$（最快）→ **单项满分**
- Actual 在两者之间按比例线性计分，八个单项独立求和得总分，精确落在 0∼50 之间。

#### 参考值

| Case | 指标 | 最慢 $B$（ms） | 最快 $Best$（ms） |
|------|------|:---:|:---:|
| T1 | TTFT | 4000.00 | 3500.00 |
| T1 | TPOT | 38.00 | 30.00 |
| T2 | TTFT | 15000.00 | 11800.00 |
| T2 | TPOT | 38.00 | 30.00 |
| T3 | TTFT | 52000.00 | 40000.00 |
| T3 | TPOT | 38.00 | 30.00 |
| T4 | TTFT | 130000.00 | 94000.00 |
| T4 | TPOT | 38.00 | 30.00 |

> 最慢值取未优化参考实现实测值，最快值取当前已知最优或理论下限。


## 5. 评测说明

CI 会根据仓库目录自动扫描并调度执行。

### 5.1 执行方式

在 `tecovllm-modelzoo-{队名}` 仓库目录下执行：

```bash
cd tools/ci_pipline && python run_ci.py
```

### 5.2 评测流程

CI 按以下顺序自动执行，前一步不通过则终止后续流程：

| 步骤 | 内容 | 说明 |
|------|------|------|
| 1. 启动服务 | 启动 vLLM 推理服务 | 通过 `run.sh` 启动，自动等待服务就绪 |
| 2. 精度测试 | 运行精度评测 | 通过标准见 [3.2 精度评测基准](#32-精度评测基准) |
| 3. 性能测试 | 精度通过后自动执行 | 通过标准见 [4.2 性能指标](#42-性能指标) |
| 4. 结果提取 | 提取 TTFT、TPOT 等指标 | 按 [4.4 性能评分规则](#44-性能评分规则) 计算最终得分 |
